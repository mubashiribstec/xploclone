## PR #1 findings

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1.1 | **Major** | Per-sentence pcm16 streaming cached the chunks produced so far in its `finally` block, **even when synthesis failed mid-stream**. The next identical request got the truncated audio as a full **200 cache hit**. The failed stream was also always counted as a 200. | `ad24c9c`: only a stream that delivered every chunk is cached or counted as 200. An engine failure records 503 with its error code. An early close (hang-up) records 499 `client_disconnected`. |
| 1.2 | Minor | Whole-file pcm16 responses (e.g. cache hits) were named `*.wav`. | `ad24c9c`: the extension follows the format. |
| 1.3 | Minor | ruff UP038 ×9 in `scripts/benchmark/acoustic_profile.py`. | `ad24c9c` |
| 1.4 | Minor, open | M5: no CI workflow in the repo. | Not fixed: needs a token with the `workflows` permission (owner-side commit). |
| 1.5 | Minor, open (noted) | Web session cookie is a fixed HMAC: it never expires server-side, and logout does not revoke it. The 12 h limit is only the cookie's `maxAge`. No brute-force limit on `/api/auth/login`. | Acceptable for a private single-owner app on localhost/VPN. Revisit if it is ever exposed. |
| 1.6 | Minor, open (noted) | `METRICS.record` is called with the client-supplied `voice_id` *before* auth (unknown-voice 400s), so unauthenticated callers can grow the metrics label set without limit. | Low risk while the API is not public. |

Checked and fine: Urdu (`mubashir-ur`) returns 503 `engine_unavailable` on every path, including streaming. Unknown voices are 400, never a fallback. API key comparison is constant-time on the SHA-256. Synthesis runs off the event loop. The revision pin is enforced. The queue slot is released on every path; a suspected leak on client disconnect was **not reproducible** with Starlette 0.52.1.

## PR #2 findings

| # | Severity | Finding | Fix |
|---|---|---|---|
| 2.1 | **Major (security)** | The app never logs the `?key=` WebSocket API key, **but uvicorn's own log does**: it prints WebSocket paths with the query string. Verified live: `"WebSocket /v1/tts/stream?key=<plaintext key>" [accepted]`. Both Dockerfiles run uvicorn with that logging on. | `dc7808d`: a redaction filter on the uvicorn and xploclone loggers. Re-verified live: 0 occurrences of the key. The WS also accepts `Authorization: Bearer` (the header wins), for servers and telephony adapters. |
| 2.2 | **Major** | The rendered-greeting cache and single-flight key (`_speech_key`) **ignored prosody**. On the WS, a `firm` request after a `natural` one for the same text replayed the cached `natural` audio. That is a silent substitution; the HTTP cache already keys on prosody. | `1252c6c`: prosody is now part of the key. |
| 2.3 | Major (honesty) | On a cache hit the done frame reported **`rtf: 0.0`**, which reads as a measurement. | `1252c6c`: on a hit, `rtf: null` and `cache: "hit"`. A synthesised request reports `cache: "miss"` with the measured RTF. |
| 2.4 | Major | A caller **hanging up mid-stream** was logged at ERROR as "streaming synthesis failed" and counted as 503 `synthesis_failed`. The error frame sent to the closed socket then raised an unhandled exception out of the handler. That skews the failure metrics the evaluation relies on. | `1252c6c`: recorded as 499 `client_disconnected`, and the connection loop ends cleanly. The slot was already released correctly; that is now also tested. |
| 2.5 | Major (latent, Phase 2) | `run_call`'s default synthesizer **bypassed the shared synthesis slot**. A phone call could synthesise on the GPU alongside `POST /v1/tts`, contradicting the PR's "one queue" claim. Not reachable yet, because no route wires `run_call` in Phase 1. | `1252c6c`: it now takes `SYNTHESIS_QUEUE` (`EngineBusy` when full). Renders are shared only between callers with the same synthesizer. Without that rule, the WS (which holds the slot) could wait on a render that is itself waiting for the slot. |
| 2.6 | Minor | ruff ×24, 7 files unformatted, 2 mypy errors (`render_ulaw(**dict)`). | `83df2fa` (no behaviour change). |
| 2.7 | Addition | The codec's only `audioop`-free pin was 7 golden values. | `1252c6c`: an exhaustive `audioop` test, plus SHA-256 digests of `audioop`'s output over the **full** input domains. That pin runs on every Python, with no `audioop` needed. |

Checked and fine: the 9 audit fixes listed in `docs/TELEPHONY-PORT-PHASE1.md` (float rejection and int16 clipping, NaN/inf sanitising, lazy torch, malformed JSON keeps the socket open, 5,000-char cap and string check, voice before length, µs `gen_time_s`, 0x7F/0xFF dual zero, no silent voice fallback). HTTP and WS share one rate-limit bucket and one queue (the same objects). Raw-JSON prosody values are validated: `NaN`, strings and unhashable presets are rejected. No phone numbers are stored (call ids are masked). No caller audio is stored (the announcement responder discards inbound audio). Per-call tokens are single-use, TTL-bound and compared in constant time. The `MediaStreamProvider` contract is a `Protocol`, and no provider adapter exists (Twilio Phase 2 stays parked).

Minor, noted, not changed: when a client disconnects during a `to_thread` synthesis call, the slot is released while that one chunk's thread finishes on the GPU (threads cannot be cancelled). This applies to the HTTP pcm16 path and the WS alike. The overlap is at most one chunk.
